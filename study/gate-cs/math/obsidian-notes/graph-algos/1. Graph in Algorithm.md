## 📌 Notations

A graph is represented as:

$$G = (V, E)$$

Where:

- $V$ = set of **nodes** (vertices)
- $E$ = set of **edges**

---

## 🔗 Graph Connectivity

### Undirected Graph Connectivity

|Term|Definition|
|---|---|
|**Connected**|For _all_ pairs of vertices $u, v$ — there exists a **path** from $u$ to $v$|
|**Complete** (Fully Connected)|For _all_ pairs of vertices $u, v$ — there exists an **edge** from $u$ to $v$|

```
Connected Graph         Disconnected Graph
    o---o                   o   o
   / \ /                   / \   \
  o   o                   o   o   o
```

### Directed Graph Connectivity

|Term|Definition|
|---|---|
|**Strongly Connected**|There is a path from **every** vertex to **every other** vertex|
|**Weakly Connected**|There is a path from every vertex to every other vertex, **ignoring direction** of edges|

> [!important] Key Note If "connected graph" is mentioned **without** specifying directed or undirected → consider **undirected**. The concept of "connected" only exists in undirected graphs. For directed graphs, we use **strongly connected** and related concepts.

## 🗂️ 3.1 Introduction to Graphs

### Storing Graphs

Need to store **both** the set of nodes $V$ and set of edges $E$.

---

### Adjacency Matrix

$$A(i,j) = 1 \iff (i,j) \in E$$

- Size: $V \times V$ matrix
- Symmetric for **undirected** graphs

```
Undirected Example:        Directed Example:
   a b c d                    a b c d
a [0 1 0 1]              a  [0 0 0 1]
b [1 0 1 1]              b  [1 0 1 0]
c [0 1 0 1]              c  [0 0 0 0]
d [1 1 1 0]              d  [0 1 1 0]
```

---

### Adjacency List

Each vertex stores a **list of its neighbors**.

```
Undirected:              Directed:
a → [b] → [d]           a → [d]
b → [a] → [d] → [c]     b → [a] → [c]
c → [d] → [b]           c → (empty)
d → [a] → [b] → [c]     d → [c] → [b]
```

> [!tip] Key Observation
> 
> - **Undirected graph:** Number of external nodes in adjacency list = **2E** _(Each list represents the degree of that node)_
> - **Directed graph:** External nodes = **E** = sum of out-degrees of all vertices

---

### ⚖️ Adjacency List vs Adjacency Matrix Comparison

|Operation|Adjacency List|Adjacency Matrix|
|---|---|---|
|**Space**|$\Theta(V + E)$|$\Theta(V^2)$|
|**Test if** $u \to v \in E$|$\Theta(1 + \deg(u))$|$\Theta(1)$|
|**List v's neighbors**|$\Theta(1 + \deg(v))$|$\Theta(V)$|
|**List all edges**|$\Theta(V + E)$|$\Theta(V^2)$|
|**Insert edge uv**|$\Theta(1)$|$\Theta(1)$|
|**Delete edge uv**|$\Theta(1 + \deg(u) + \deg(v))$|$\Theta(1)$|

---

### 📊 Algorithm Runtime & Graph Density

Graph algorithm runtimes depend on $|V|$ and $|E|$.


|Graph Type|Relation|
|---|---|
|**Dense graph** (complete graph)|$\|E\| \approx \|V\|^2$|
|**Sparse graph**|$\|E\| \approx \|V\|$|

## 🔍 Graph Traversal & Search

> Graph traversal is different from tree traversal:
> 
> - Trees: ordered, obvious start, obvious end
> - Graphs: **any order**, **any start**, end is **not obvious**

**Commonly used search methods:**

- Breadth-First Search (BFS)
- Depth-First Search (DFS)

---

## 🔎 3.2 Searching Algorithm

### Whatever-First Search (General Framework)

```
Whatever-first-search(G, s):
    put s in the bag
    while bag is not empty (no marked left):
        Extract v from bag
        if v is unmarked:
            mark v
            for each edge (v, w):
                put w into the bag
```

> [!note] Bag Implementation
> 
> - **Stack** → Depth-First Search (DFS)
> - **Queue** → Breadth-First Search (BFS)

> [!warning] Simply deleting nodes instead of marking them is not effective because the node may be added again due to its neighbors and if being in bag means to visit then we have a loop!

## 🌲 3.2.1 Depth-First Search (DFS)

> **Thumb rule:** If there are no new nodes during traversal to visit → **backtrack**

### DFS Tree Example

```
DFS(a):
    a
    ↓
    b
   / \
  c   d
      |
      e → f
```

_(This forms the Depth-First Tree / DFT)_

### Discovery & Finish Times

| Term                       | Definition                                               |
| -------------------------- | -------------------------------------------------------- |
| **Start / Discovery time** | Time at which a vertex is visited **for the first time** |
| **Finish time**            | Time at which a vertex is visited **last time**          |

---
### Implementation of DFS

```python
DFS_Visit(u):
    d[u] = time++          # record discovery time
    visited[u] = true
    for each v adjacent to u:
        if not visited[v]:
            DFS_Visit(v)
    f[u] = time++          # record finish time (assign time to node)
```

```python
DFS(G):
    for each vertex u in vertices:
        visited[u] = false    
    time = 0
    for each u in vertices:
        if visited[u] == false:
            DFS_Visit(u)
```

**Time complexity:**
Focus on what is being done. The DFS algo visits each node and does the simple tasks of marking them, and updating time.
So, TC = "nodes" in the representation.

| Method           | Time to explore all nodes                       | Node             |
| ---------------- | ----------------------------------------------- | ---------------- |
| Adjacency List   | $1 + \deg(v_i)$ per vertex → Total: $O(V + 2E)$ | Linked nodes     |
| Adjacency Matrix | $V$ per vertex → Total: $O(V^2)$                | The matrix cells |

---

### 📐 DFS Parentheses Theorem

> **Lecture 22a**

In any DFS of a **directed or undirected** graph $G = (V, E)$, for any two vertices $u$ and $v$, **exactly one** of the following three conditions holds:

1. **Disjoint intervals:**
    
    - $[u.d,\ u.f]$ and $[v.d,\ v.f]$ are entirely disjoint
    - Neither $u$ nor $v$ is a descendant of the other in the DFS forest
2. **u inside v:**
    
    - $[u.d,\ u.f] \subset [v.d,\ v.f]$
    - $u$ is a **descendant of** $v$ in a DFS tree
3. **v inside u:**
    
    - $[v.d,\ v.f] \subset [u.d,\ u.f]$
    - $v$ is a **descendant of** $u$ in a DFS tree

### 🏷️ DFS Edge Classification

> **Lecture 22b**
> https://medium.com/@vikramsetty169/edge-types-in-graph-traversal-1c3545c61234

We first find DFS tree, which is directed.
The edges define kids and papa set for each vertex.

Now using this set and the edges of the original graph, we categorize the the (latter) edges as:

| Edge Type        | Definition                                         |
| ---------------- | -------------------------------------------------- |
| **Tree edge**    | Edge in the DFS forest                             |
| **Forward edge** | Not a tree edge; goes from **papa → kid**          |
| **Back edge**    | Not a tree edge; goes from **kid → papa**          |
| **Cross edge**   | Not a tree edge; neither papa nor kid relationship |

#### Example:
![[../../attachments/Pasted image 20260313085126.webp]]

```
Tree edges:    (a,b), (a,c), (b,d), (d,e), (e,f)
Forward edges: (a,d), (a,f), (d,f)
Back edge:     (e,a)
Cross edges:   (g,h), (c,d), (c,e), (h,d)
```

#### Edge Types in DFS — Summary Table

| Graph Type     | Possible Edge Types        |
| -------------- | -------------------------- |
| **Directed**   | Tree, Cross, Back, Forward |
| **Undirected** | Tree, Back                 |

> [!note] Why no Cross/Forward edges in Undirected DFS? In undirected graphs, direction of edges is not defined — so cross edges would become subtree edges, and similarly there are **no forward edges**.

> [!important] Key Theorem **A graph has a cycle if and only if there is a back edge**
> 
> Equivalently: **No back edge ↔ Acyclic graph**
> 
> This holds for both directed and undirected graphs.

### 📋 Topological Sort

**Algorithm:**

1. First select a node with **indegree = 0**
2. If no such node exists → **topological ordering is NOT possible** (graph has a cycle)
3. If found → remove it, find next vertex with indegree 0, repeat

**Using DFS for Topological Sort:**

- First find vertex with indegree zero
- For all neighbors $u$ → decrease indegree by 1

### Cut Vertex / Articulation Point
https://www.youtube.com/watch?v=nddmCmp1Bng

> **Lecture 23d**

> **Definition:** An articulation point of $G$ is a vertex whose **removal disconnects** $G$.

#### How to Find Articulation Points (DFS-Based Approach)

**Case 1 — Root of DFT:**

- Root is an AP **only when** it has **more than one child**
- If it has only one child → deleting the root cannot disconnect the graph

**Case 2 — Non-root of DFT:**

- A non-root is an AP **if and only if** there exists **one subtree** of the node such that **none** of its descendants are directly connected to an ancestor

> [!warning] Modified Case 2 If one child of node 6 is connected to 6's ancestor → 6 may NOT be an AP even with 2 children. Hence: A non-root is AP iff **at least one subtree** has no back edge to an ancestor.

**Implementation:**

- Maintain an array for **start/discovery time** of each node
- Maintain another array for the **lowest discovery time** reachable from a node (tracks back edges)

---

### Biconnected Components

A graph is **biconnected** if:

1. The graph is **connected**
2. After removing **any** vertex and all its associated edges, the graph **still remains connected**

> Equivalently: A graph is biconnected if it has **no articulation points**

## 🌊 3.2.2 Breadth-First Search (BFS)

> **Lecture 24a**

> At a time, we visit all neighbors of a node separated by **one edge** (level by level).

### BFS Algorithm

```python
BFS(G, v):
    # Initialise visited of all nodes to false
    visited[v] = true
    enqueue(Q, v)
    while Queue is not empty:
        u = dequeue(Q)
        for each adjacent x to u:
            if visited[x] == false:
                visited[x] = true
                enqueue(Q, x)
```

**Time Complexity:**
We are doing the same thing here as we did in DFS....just ordering is different

|Representation|Time|
|---|---|
|Adjacency List|$O(V + E)$|
|Adjacency Matrix|$O(V^2)$|

## ⚙️ Applications of BFS

> **Lecture 24c**

### 🟦 [[gate-cs/math/Bipartite Graph]] Detection

> [!note] Definition **A graph is bipartite if and only if there is NO odd-length cycle**
> 
> _(It can have even-length cycles OR no cycles at all)_

In BFS trees, only **tree edges** and **cross edges** exist. Two cases:

**Case 1: No cross edges** → Graph is **definitely bipartite** (alternate levels form two groups)

```
Group 1: [level 0, level 2, level 4, ...]
Group 2: [level 1, level 3, level 5, ...]
```

**Case 2: Cross edge exists**

|Cross edge between...|Result|
|---|---|
|Nodes at **same level** (level $i$ to $i$)|100% **odd cycle** → NOT bipartite|
|Nodes at level $i$ and level $i+1$|No odd cycle possible|

**Implementation:** Check cross edges between nodes at the same level.

- If edge has 2 vertices where $d[v] = d[u]$ → **odd cycle → not bipartite**
- If $d[v] = d[u] + 1$ → fine (adjacent levels)

---

### 🔌 BFS for Disconnected Graphs

```cpp
vector<bool> Visited(number_of_vertices, false);
for (int u = 0; u < number_of_vertices; u++)
    if (Visited[u] == false)
        BFS(u, adj, Visited);
```

- Maintain a **global array** of vertices to track visited status
- Time complexity: $O(V \times E)$ naively, but since we only visit unvisited nodes → $TC = O(V + E)$

### 🧩 Finding Connected Components

Both **BFS** and **DFS** can find the number of components in a graph.

**BFS approach:**

- Maintain an array where each element is assigned a **component number**
- Any element with value **0** implies it belongs to a separate (unvisited) component

**DFS approach:**

- Already covered — count the number of DFS calls from the outer loop

## 🗺️ Quick Reference: BFS vs DFS

| Property                          | BFS               | DFS                        |
| --------------------------------- | ----------------- | -------------------------- |
| **Data Structure**                | Queue             | Stack (or recursion)       |
| **Time Complexity**               | $O(V + E)$        | $O(V + E)$                 |
| **Edge types (directed)**         | Tree, Cross, Back | Tree, Cross, Back, Forward |
| **Edge types (undirected)**       | Tree, Cross       | Tree, Back                 |
| **Cycle detection**               | ✅                 | ✅ (back edge)              |
| **Shortest path (unweighted)**    | ✅                 | ❌                          |
| **Topological sort**              | ✅ (Kahn's)        | ✅                          |
| **Connected components**          | ✅                 | ✅                          |
| **Bipartite check**               | ✅                 | ✅                          |
| **Articulation points**           | ❌                 | ✅                          |
| **Biconnected components**        | ❌                 | ✅                          |
| **Strongly connected components** | ❌                 | ✅ (Kosaraju/Tarjan)        |
