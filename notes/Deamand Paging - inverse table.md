During normal execution, the MMU translates virtual addresses to physical addresses using standard forward page tables ($\text{VPN} \to \text{PFN}$). However, when RAM is full and a page fault occurs, the page replacement algorithm selects an occupied **physical frame** ($\text{PFN}$) to reclaim. Before this frame can be reused, the OS must invalidate the previous resident page's entry ($\text{valid} \leftarrow 0$) in its owning process's page table and flush matching TLB entries. Without a dedicated reverse mapping, the operating system would be forced to perform an exhaustive, time-consuming linear search across every page table of every active process in RAM just to determine who owns that physical frame.

To eliminate this bottleneck, the OS maintains a system-wide **Frame Table** (or Core Map) indexed directly by physical frame number ($\text{Index} = \text{PFN}$). Each entry contains the owner information $[\text{PID} \mid \text{VPN}]$, allowing an immediate $O(1)$ constant-time lookup to find the owning process and clear its valid bit before loading the new page. Because this table tracks physical RAM rather than virtual memory, it requires strictly one entry per physical frame, meaning its total length remains constant regardless of how many processes are created or running in the system.
